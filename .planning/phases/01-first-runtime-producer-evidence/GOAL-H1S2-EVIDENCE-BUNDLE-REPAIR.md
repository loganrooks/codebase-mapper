## Terms Used In This Brief

### Runtime Surface Mapper Output

A `surface_map` artifact is runtime Surface Mapper output when:

- `artifact_type == "surface_map"`, and
- `produced_by` does **not** start with `cbm-baseline-`, and
- `produced_by` does **not** start with `dev-fixture-`.

Example from H1.S1:

```json
"artifact_type": "surface_map",
"produced_by": "surface-mapper@1.2"
```

### Real Skeptic Output

A Skeptic artifact is real only when its producer is a runtime Skeptic producer, for example:

```text
skeptic@1.2
```

It is **not** real Skeptic output if it is:

- `dev-fixture-*`
- `codex-cli-smoke@*`
- generated by fallback behavior when `--codex-skeptic-mode none`

### Unknown Edge

An unknown edge is any edge where:

```json
"kind": "unknown"
```

The code must not depend on a literal id such as:

```text
edge-unknown-001
```

An artifact may still happen to contain that id, but acceptance logic must not require it.

## Current Concrete Failure Examples

Use the H1.S1 benchmark packet as the concrete fixture.

### Failure Example 1 — Runtime Surface Map Described As Deterministic

The H1.S1 `surface-map.json` is runtime output:

```json
"produced_by": "surface-mapper@1.2"
```

But the H1.S1 handoff artifact list describes it as:

```text
Draft deterministic surface map with explicit unknown dependency edge.
```

That is wrong for a non-baseline runtime Surface Mapper output.

### Failure Example 2 — Handoff Coverage Does Not Promote Runtime Surface Map Coverage

The H1.S1 `surface-map.json` reports:

```yaml
files_in_scope: 12
files_examined_directly: 7
files_inspected_via_extractor: 12
files_unread_in_scope: 0
```

The H1.S1 handoff reports:

```yaml
files_in_scope: 12
files_examined_directly: 1
files_inspected_via_extractor: 12
files_unread_in_scope: 11
```

For a handoff promoting a runtime Surface Mapper map, the handoff coverage and coverage caveats must derive from the runtime surface map, not from deterministic baseline fallback/card coverage.

### Failure Example 3 — Handoff Body Says Phase A Mechanical Gates

The H1.S1 handoff body says:

```text
Phase A mechanical gates produced a draft handoff.
```

That is misleading when the promoted `surface-map.json` was produced by `surface-mapper@1.2`.

### Failure Example 4 — Dev-Fixture Skeptic Fallback Is Counted Like A Review

The H1.S1 benchmark result says the run used:

```text
--codex-skeptic-mode none
```

But the handoff still includes:

```text
.research/run-mcp-git-surface-mapper-h1s1-6/skeptic-review/surface-map.md
```

and its gate summary says:

```yaml
skeptic_review:
  artifacts_reviewed: 1
  challenges_logged: 0
```

When no real Skeptic ran, a dev-fixture or fallback review must not be counted as a real Skeptic review.

### Failure Example 5 — Unknown Edge Requirement Is Literal-ID Shaped

The H1.S1 map contains an unknown edge with id:

```text
edge-unknown-001
```

The accepted review blocker says any requirement depending on this literal id must be replaced by a lookup for at least one edge with:

```json
"kind": "unknown"
```

### Failure Example 6 — Benchmark Packet Does Not Preserve Full Runtime Evidence

H1.S1 benchmark evidence references `.research/<run_id>/...` paths and hashes. The benchmark packet must preserve enough of the `.research/<run_id>/` tree to audit those references, including `logs/` and `codex_outputs/`, or it must stop citing non-preserved files.

### F6 — Repair-Pass Evidence Preservation Fix

This concerns runtime producer repair behavior.

If the first model output is invalid and a repair pass is attempted, preserve all evidence.

Required success case:

- original invalid output is preserved in `codex_outputs/`
- repair prompt/input is preserved if generated
- repaired valid output is preserved in `codex_outputs/`
- stdout and stderr for both attempts are preserved in `logs/`
- run manifest records both attempts or a parent step with enough child-attempt metadata
- final status is successful only if the repaired artifact validates

Required failure case:

- original invalid output is preserved
- repair output is preserved even if invalid or empty
- stdout/stderr are preserved
- manifest status is failed or interrupted with an explicit cause
- no handoff claims the artifact passed

Use fake executables for tests. Do not run a live model for this goal.

If no repair pass currently exists, do not invent a broad repair subsystem. Instead, add tests around the existing invalid-output path and preserve available partial outputs/logs.
